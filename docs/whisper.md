# Транскрибация: whisper.cpp

Программа умеет превращать речь из видео и аудио в текст локально — без интернета
и без отправки файлов куда-либо. Под капотом [whisper.cpp](https://github.com/ggml-org/whisper.cpp)
(порт модели OpenAI Whisper на C++) и уже знакомый проекту FFmpeg.

Файлы: `whisper.go` — пайплайн и HTTP-обработчики, `whisper_install.go` — установка
бинарника и моделей, `diskfree_unix.go` / `diskfree_windows.go` — проверка места на диске.

---

## Как это работает

```
видео/аудио ──ffmpeg──▶ wav 16 кГц моно ──whisper-cli──▶ txt / srt / vtt
                (temp)                       (temp)        рядом с исходником
```

1. **Проба файла.** `ffmpeg -i <файл>` — из его отчёта берём длительность и проверяем,
   есть ли вообще звуковая дорожка.
2. **Извлечение.** `ffmpeg -vn -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le` — whisper
   принимает только 16 кГц моно. Wav пишется во временную папку системы
   (`vdown-whisper-*`), а не в память: у трёхчасового фильма это ~350 МБ.
3. **Распознавание.** `whisper-cli -m <модель> -f <wav> -l ru -pp -otxt|-osrt|-ovtt`.
4. **Результат** переносится из временной папки к исходному файлу. Если такое имя
   занято — рядом появится `имя (2).txt`, ничего не затирается.

Прогресс: этап извлечения занимает первые 10 % шкалы, распознавание — остальные 90 %.
Проценты берутся из строк `whisper_print_progress_callback: progress = NN%` и из
таймкодов сегментов (`[00:01:23.000 --> ...]`), ETA считается по времени текущего этапа.

Отмена на любом этапе убивает процесс через `context` и удаляет временную папку.

## Установка whisper и моделей

Принцип тот же, что для yt-dlp и FFmpeg (`deps.go`): **ничего не ставим в систему**.

Поиск бинарника: `tools/whisper-cli` → `whisper-cli` или `whisper-cpp` в `PATH`
(например, от `brew install whisper-cpp`) → если нигде нет, ставим свой.

| ОС | Как получаем |
|----|--------------|
| macOS (arm64) | Собираем из исходников v1.9.1 **с Metal** (`-DGGML_METAL=ON -DGGML_METAL_EMBED_LIBRARY=ON`) — на M-чипах это разница в разы. Шейдеры зашиты внутрь бинарника, рядом ничего не нужно |
| macOS (Intel), Linux | Та же сборка из исходников, без Metal |
| Windows | Готовый `whisper-bin-x64.zip` из релиза: `whisper-cli.exe` + `.dll` рядом, в `tools/whisper/` |

Готовых бинарников под macOS в релизах whisper.cpp нет — поэтому сборка. Для неё нужен
cmake: берём системный, а если его нет — качаем портативный (`tools/cmake`) и **удаляем
после успешной сборки**, чтобы не оставлять 200 МБ мусора. Компилятор берётся из
Xcode Command Line Tools (на маке они почти всегда есть; иначе `xcode-select --install`).

Замеры на M5 (10 ядер): скачивание cmake ~90 МБ, исходников ~11 МБ, сама сборка —
**13 секунд**, итоговый бинарник 3.2 МБ, статический.

### Модели

Качаются по требованию с HuggingFace в `tools/models/`:

| Модель | Размер | Когда нужна |
|--------|--------|-------------|
| `base` | 141 МБ | Черновая расшифровка, «о чём вообще ролик» |
| `small` | 465 МБ | **По умолчанию.** Нормальный русский текст |
| `medium` | 1.4 ГБ | Сложный звук, акценты, важна точность |
| `large-v3` | 2.9 ГБ | Максимум качества, если не жалко времени и места |

Скачивание — с докачкой: недокачанное лежит в `имя.bin.part`, при повторе загрузка
продолжается с этого места (HTTP Range), готовый файл появляется атомарным
переименованием. Перед скачиванием проверяется свободное место. Если соединение
замолчало на 90 секунд — загрузка честно падает с ошибкой, а `.part` сохраняется.

## Какую модель выбрать: замеры на русском

Тестовый материал — синтезированная русская речь (`say -v Milena`), два файла:
короткий 1:14 и длинный 30:45. Железо: MacBook M5, 24 ГБ, whisper.cpp v1.9.1 с Metal.

**Через API целиком (ffmpeg + загрузка модели + распознавание), запись 30:45:**

| Модель | Время | На минуту речи | Во сколько раз быстрее реального времени |
|--------|-------|----------------|------------------------------------------|
| `base` | 34 с | ~1.1 с | ~54× |
| `small` | 71 с | ~2.3 с | ~26× |
| `medium` | 167 с | ~5.4 с | ~11× |

**Чистое время распознавания (файл 1:14, модель уже прогрета):**
`base` — 1.3 с, `small` — 2.6 с, `medium` — 6.7 с.

**Качество на том же тексте (одна и та же фраза):**

| Модель | Что получилось |
|--------|----------------|
| эталон | «…субтитры SRT и субтитры VTT. Модель base работает быстро, но путает окончания и редкие слова, например: конвейер, диаризация, оркестрация» |
| `base` | «…субтитра **ясоортии** и субтитра **витетей**. Модель бейс работает быстро… например, **конвьюер, дирязация, аркистрация**» |
| `small` | «…субтитры SRT и субтитры VTT. Модель Small заметно точнее… например, Conveyor, Deerization, Orchestration» *(редкие термины уезжают в латиницу, но структура и обычная речь — верные)* |
| `medium` | «…субтитры SRT и субтитры VTT… например, конвейер, **диализация**, оркестрация… хотя весит полтора гигабайта» *(самый чистый русский; из минусов — слепил числа «251473212»)* |

**Вывод и рекомендация: по умолчанию `small`.** Она даёт связный, читаемый русский
текст, в 2.4 раза быстрее `medium` и втрое меньше по весу. `base` годится только
как «быстро понять, о чём речь»: на русском она заметно врёт. `medium` берите, когда
качество важнее времени: реальная (не синтезированная) речь, шум, несколько дикторов,
акценты — там разрыв между `small` и `medium` больше, чем на чистом TTS.

Значение по умолчанию задано в `whisper_install.go`: `defaultWhisperModel = "small"`,
`defaultWhisperLang = "ru"`.

## Чего whisper НЕ умеет

- **Диаризации нет.** Whisper не разделяет говорящих: диалог двух человек выйдет
  сплошным текстом, без пометок «кто сказал». Отдельные метки спикеров требуют
  постобработки другими инструментами (pyannote и подобные) — в программе этого нет.
  Та же оговорка отдаётся в API полем `note` в `/api/whisper/status`.
- Пунктуация и заглавные буквы расставляются моделью «на слух» и иногда врут.
- Числа и термины на русском модели любят склеивать или писать латиницей.
- Музыка и песни распознаются плохо — это модель для речи.

## HTTP API

Всё локально, на том же порту, что и веб-оболочка.

### POST /api/transcribe

```json
{"path":"/Users/me/видео/лекция.mp4","lang":"ru","model":"small","format":"srt"}
```

Ответ: `{"jobId":"t1785526908-1"}`.

Значения по умолчанию: `lang=ru`, `model=small`, `format=txt`. Поддерживаются
`file://`-ссылки и `~` в начале пути.

Ошибки — `400` с полем `code`, чтобы интерфейс мог отреагировать по-разному:

| code | Когда |
|------|-------|
| `bad_path` | файла нет, указана папка, путь пустой |
| `bad_format` | расширение не медийное или запрошен не txt/srt/vtt |
| `bad_lang` | язык не `auto` и не двухбуквенный код |
| `bad_model` | модели нет в каталоге |
| `whisper_missing` | whisper.cpp не установлен |
| `model_missing` | модель не скачана |

### GET /api/transcribe/progress?id=…

```json
{"state":"transcribing","percent":41,"eta":43,"error":"","outPath":"","preview":"Здравствуйте…","stage":"Распознавание речи"}
```

`state`: `queued` → `extracting` → `transcribing` → `done` | `error`.
`percent` — общий прогресс (0–100), не откатывается назад. `eta` — секунды.
`preview` — первые ~800 символов текста, появляются по ходу распознавания.
`stage` — необязательное пояснение для человека (сверх контракта): «Извлечение звука»,
«Загрузка модели «medium»», «Скачивание модели «small» (465.0 МБ)».
Отменённая задача выглядит как `state=error`, `error="Отменено"`.

### POST /api/transcribe/cancel

```json
{"id":"t1785526908-1"}
```

Работает на любом этапе, включая скачивание модели.

### GET /api/whisper/status

```json
{"installed":true,"busy":false,"default":"small",
 "models":[{"name":"base","size":147951465,"downloaded":true}, …],
 "note":"whisper не разделяет говорящих…"}
```

`busy` — занят ли единственный слот: идёт транскрибация или установка.

### POST /api/whisper/install

```json
{"model":"small"}
```

Ответ: `{"jobId":"model:small"}` — прогресс смотрится тем же `/api/transcribe/progress`.
Если whisper ещё не установлен, задача сначала поставит его (первые 20 % шкалы),
затем скачает модель. Пустая модель (`{"model":""}`) — поставить только whisper,
id задачи будет `model:whisper`. Повторный запрос во время работы возвращает ту же задачу.

### POST /api/reveal (сверх контракта)

```json
{"path":"/Users/me/видео/лекция.srt"}
```

Показывает файл в Finder / проводнике — из браузера это иначе не сделать.

## Edge cases и как они закрыты

| Ситуация | Поведение |
|----------|-----------|
| В видео нет звуковой дорожки | Проверяем до всякой работы, ошибка «в файле нет звуковой дорожки — распознавать нечего» |
| Многочасовой файл | Wav пишется во временную папку системы и удаляется всегда (в том числе при отмене и ошибке); в памяти ничего не держим |
| Мало места под wav | Считаем заранее: 32 КБ на секунду звука + запас; при нехватке — понятная ошибка с цифрами |
| Мало места под модель | Сверяем свободное место с известным размером модели до начала загрузки |
| Два запроса разом | Очередь на один процесс whisper: вторая задача висит в `queued`, `busy=true` в статусе |
| Очередь переполнена (32) | `503` с текстом «очередь транскрибации переполнена» |
| Пробелы и кириллица в пути | Аргументы передаются процессу списком, без шелла и экранирования; проверено тестом и живым прогоном на `Мои видео/тестовое видео 01.mp4` |
| Модель не скачана | `400 model_missing` — интерфейс предлагает установку |
| whisper не установлен | `400 whisper_missing` |
| Отмена при скачивании модели | Процесс останавливается, `.part` сохраняется для докачки |
| Отмена при извлечении/распознавании | Процесс убивается, временная папка удаляется, файл результата не создаётся |
| Обрыв или «залипшая» сеть | Нет данных 90 секунд — ошибка с подсказкой; докачка продолжится с этого места |
| Файл результата уже есть | Пишем `имя (2).txt`, не затираем |
| Папка с видео только для чтения | Ошибка «не удалось сохранить результат рядом с видео» (whisper пишет во временную папку, перенос — последний шаг) |
| Программу убили во время работы | Старые `vdown-whisper-*` старше суток удаляются при следующем запуске |

## Тесты

```bash
go test ./...                                    # юнит-тесты, интеграционные скипаются
VDOWN_TOOLS_DIR=$PWD/tools go test -v ./...      # плюс реальный прогон whisper
```

- Юнит: разбор прогресса whisper/ffmpeg/cmake, разбор сегментов, сборка аргументов
  whisper и ffmpeg, валидация запроса, подбор имени файла, докачка/отмена/зависание
  загрузки (на `httptest`), монотонность прогресса.
- Интеграционные: реальный прогон whisper с моделью `base` на сгенерированном
  FFmpeg аудио (путь с пробелом и кириллицей) и проверка видео без звуковой дорожки.
  Скипаются, если whisper или модель не установлены.

`VDOWN_TOOLS_DIR` — переменная окружения, задающая папку зависимостей (по умолчанию
`tools/` рядом с исполняемым файлом). Нужна тестам и переносным установкам.

## Заметки на будущее

- FFmpeg для Apple Silicon теперь качается нативный arm64 (`deps.go`): сборка
  evermeet — x86_64 и без Rosetta просто не запускается («bad CPU type in executable»).
- Версии whisper.cpp и cmake зафиксированы в `whisper_install.go` — обновление
  делается осознанно, а не «что там сегодня в latest».
- `large-v3` в каталоге есть, но вживую не гонялась: 2.9 ГБ. Ожидаемо примерно
  вдвое медленнее `medium`.
