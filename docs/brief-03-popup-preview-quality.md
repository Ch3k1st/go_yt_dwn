# Бриф 03 — попап расширения: превью и выбор качества

**Дата:** 2026-08-01. Запрос владельца: «нашли видео — там же маленькое превью и выбор
качества», чтобы не открывать программу ради каждой мелочи.

Сейчас попап показывает имя источника, тип (HLS/файл), размер, метку «с куками» и кнопку
«Скачать». Качество из мастер-манифеста уже разбирается (`360p · 2 вар.`), но выбрать
вариант нельзя, превью нет.

## Что делаем

### 1. Превью (маленькая картинка в строке находки)

Порядок источников — от дешёвого к дорогому, каждый следующий только если предыдущий не дал:

1. **Метаданные страницы**: `og:image`, `twitter:image`, атрибут `poster` у `<video>`.
   Читать через `chrome.scripting.executeScript` по активной вкладке **в момент открытия
   попапа** — это разовое действие по жесту пользователя, разрешение `activeTab` даётся
   именно под такой сценарий. НЕ вешать постоянный content script на все страницы:
   расширение и так просит `<all_urls>` для webRequest, добавлять к этому постоянную
   инъекцию в каждую страницу — лишнее вмешательство, владелец такое не любит.
   Если `activeTab`/`scripting` по каким-то причинам не подходит — обоснуй и предложи
   замену, но постоянный content script только последним средством.
2. **Кадр из видео** через программу — новая ручка `GET /api/preview?url=…` (токен
   обязателен, как у `/api/capture`): сервер зовёт ffmpeg, вытаскивает **один кадр**
   из указанного источника (для HLS — из начала потока), отдаёт jpeg ≤320px.
   Обязательно: таймаут (5–8 с), ограничение на размер скачанного (ffmpeg с `-ss`
   и `-frames:v 1`, не тянуть весь файл), кэш по URL, чтобы попап не дёргал ffmpeg
   на каждое открытие. Если ffmpeg не смог — молча остаться без превью.
3. Нет превью — показывать аккуратную заглушку-иконку по типу источника, строка не
   должна «прыгать» из-за отсутствия картинки.

Превью подгружать **лениво**: сначала рисуется список, картинки появляются по мере
готовности (для кадра через ffmpeg это секунды).

### 2. Выбор качества

- **HLS**: мастер-манифест уже разбирается — показать варианты списком (разрешение,
  битрейт, если есть; «авто/лучшее» первым). Выбор — компактный `<select>` в строке
  находки, значение уходит в `/api/capture` (новое поле, аддитивно: `variantUrl`
  и/или `formatId`). Сервер передаёт выбор в yt-dlp корректно для HLS
  (проверь, что качается именно выбранный вариант, а не «лучшее» по умолчанию).
- **DASH**: разобрать `.mpd` (Representation: width/height/bandwidth) по той же схеме.
  Если разбор сложен — допустимо для v1 отдать в программу мастер-URL и показать
  «качество выбирается программой», но это надо честно написать в попапе.
- **Прямой файл** (mp4/webm): вариантов нет — селектор не показывать вовсе, а не
  показывать пустой.
- Помнить последний выбор пользователя (например, «лучшее» или «720p») в
  `chrome.storage.local` и предвыбирать его в следующий раз.

### 3. Мелочи, которые к этому прилагаются

- Длительность в строке, если известна из манифеста.
- Кнопка «Скачать всё» должна учитывать выбранное качество для каждой строки.
- Ширина попапа может вырасти, но не больше 480px — иначе он выглядит как окно.

## Edge cases

1. Мастер-манифест недоступен без кук/заголовков → разбор вариантов делать **в
   расширении** (оно в сессии браузера), а не на сервере.
2. Манифест огромный (сотни вариантов, live-поток) → показывать не больше ~8 строк
   качества, сгруппировав по разрешению; для live честно писать «прямой эфир».
3. Превью с чужого домена → в попапе картинка грузится напрямую из `<img>`; если
   домен отдаёт 403 без Referer — не городить прокси, просто заглушка (или уйти
   на вариант 2 с ffmpeg).
4. `og:image` бывает гигантским (2–3 МБ) → ограничить отображаемый размер, не тянуть
   в попап оригинал, если можно ограничиться `<img>` с фиксированной высотой.
5. Вкладка закрыта, пока попап открыт → не падать, показать что есть.
6. Ручка превью не должна становиться прокси-сервером для произвольных URL: принимать
   только те URL, которые уже есть в списке находок этой сессии (как сделано в
   dupe-hunter для превью файлов — валидация «только из результатов»).
7. DRM-помеченные находки: превью можно, выбор качества и скачивание — нет, как сейчас.

## Критерии готовности

- В попапе у находки видно превью (или аккуратная заглушка) и, для HLS/DASH, выбор
  качества; для прямого файла селектора нет.
- Выбранное качество реально влияет на скачанный файл — проверить на живом HLS
  (разные разрешения дают разный размер/разрешение итогового mp4).
- Разрешения расширения не расширились сверх необходимого; каждое новое объяснено
  в `extension/README.md` и `docs/extension.md`.
- Попап не тормозит: список появляется сразу, превью догружаются.
- `go vet`, `go build`, `go test` зелёные; `make app` и `make windows-app` пересобраны.
- Скриншоты попапа (light+dark) обновлены.
