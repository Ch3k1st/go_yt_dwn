# Сборка релизов

Кросс-сборка готовых бинарников под все платформы выполняется скриптом
[`build.sh`](../build.sh). Проект — на чистом Go (только стандартная библиотека), поэтому
кросс-компиляция работает без тулчейнов C (`CGO_ENABLED=0`).

## Запуск

```bash
./build.sh             # версия из git (или "dev"), все платформы
./build.sh v1.2.0      # явная версия
```

Собрать только нужные цели:

```bash
TARGETS="windows/amd64 linux/amd64" ./build.sh v1.2.0
```

## Что получается

Результат — в папке `dist/` (она в `.gitignore`). По одному архиву на платформу:

| Файл | Платформа |
| :-- | :-- |
| `v-down_<ver>_windows_amd64.zip` | Windows x64 |
| `v-down_<ver>_windows_arm64.zip` | Windows ARM |
| `v-down_<ver>_macos_amd64.tar.gz` | macOS Intel |
| `v-down_<ver>_macos_arm64.tar.gz` | macOS Apple Silicon |
| `v-down_<ver>_linux_amd64.tar.gz` | Linux x64 |
| `v-down_<ver>_linux_arm64.tar.gz` | Linux ARM |

Внутри каждого архива — исполняемый файл (`v-down` или `v-down.exe`) и `README.md`.
Бинарники маленькие (~2.5 МБ): `yt-dlp` и `ffmpeg` не вшиваются, а скачиваются при первом
запуске (см. [dependencies.md](dependencies.md)).

## Детали

- **Версия** внедряется в бинарник через `-ldflags "-X main.version=<ver>"` и доступна по
  `./v-down -version` и в баннере веб-оболочки.
- **`-trimpath`** и **`-ldflags "-s -w"`** убирают пути сборки и отладочную информацию —
  бинарник меньше и воспроизводимее.
- Список целей по умолчанию задан в начале `build.sh` (переменная `DEFAULT_TARGETS`) и
  переопределяется переменной окружения `TARGETS`.

## Раздача пользователям

Готовые архивы из `dist/` можно прикреплять к GitHub Releases. Пользователю достаточно
скачать архив под свою ОС, распаковать и запустить `v-down` — зависимости подтянутся
автоматически.
