# Веб-оболочка

С версии «update» программа по умолчанию запускает локальный веб-сервер и открывает
графический интерфейс в браузере. Консольное меню сохранено и доступно через флаг `-cli`.

## Запуск

| Команда | Что делает |
| :-- | :-- |
| `./v-down` | Веб-оболочка на `http://127.0.0.1:8080` (открывается автоматически). |
| `./v-down -addr 127.0.0.1:9000` | Веб-оболочка на другом адресе/порту. |
| `./v-down -cli` | Старый консольный интерфейс. |

Если порт 8080 занят, сервер берёт любой свободный порт и печатает фактический адрес в консоль.

## Что умеет интерфейс

1. **Выбор cookies** — выпадающий список с автоопределёнными браузерами (для обхода
   ограничений YouTube) или вариант «Без cookies».
2. **Анализ** — по нажатии запрашивает метаданные через `yt-dlp --dump-single-json` и
   показывает превью, название, канал, длительность и число просмотров.
3. **Выбор качества** — выпадающий список заполняется реальными разрешениями из ответа
   yt-dlp (например 2160p, 1080p, 720p…) плюс «Лучшее качество» и «Только аудио (m4a / mp3)».
4. **Скачать** — запускает загрузку в выбранном качестве; прогресс (проценты, скорость, ETA)
   обновляется в реальном времени. Файл сохраняется в `downloads/` под оригинальным названием.

## Устройство (файлы)

| Файл | Содержание |
| :-- | :-- |
| [`web.go`](../web.go) | HTTP-сервер, маршруты, запуск браузера, обработчики API. |
| [`ui.go`](../ui.go) | Встроенная HTML-страница (CSS + JS, без внешних зависимостей). |
| [`main.go`](../main.go) | Разбор флагов и диспетчеризация: `runWeb()` (по умолчанию) / `runCLI()`. |

## HTTP API

| Метод и путь | Назначение | Ответ |
| :-- | :-- | :-- |
| `GET /` | HTML-страница интерфейса. | `text/html` |
| `GET /api/browsers` | Список найденных источников cookies. | `[{idx, display}]` |
| `POST /api/info` | Метаданные + список качеств. Тело: `{url, cookie}`. | JSON `infoResponse` или `{error}` |
| `GET /api/download?url=…&cookie=…&quality=…` | Скачивание со стримом прогресса. | `text/event-stream` (SSE) |

### Параметр `quality`

| Значение | Селектор yt-dlp |
| :-- | :-- |
| `best` (или пусто) | `bv*+ba/best`, склейка в mp4 |
| число, напр. `720` | `bv*[height<=720]+ba/b[height<=720]/best`, склейка в mp4 |
| `audio-m4a` | `ba[ext=m4a]/ba/bestaudio` |
| `audio-mp3` | `ba/bestaudio` + `-x --audio-format mp3` |

### События SSE (`/api/download`)

| Событие | Данные | Когда |
| :-- | :-- | :-- |
| `progress` | `{percent, speed, eta}` | На каждое обновление прогресса. |
| `log` | строка | Прочие строки вывода yt-dlp. |
| `done` | `{file}` | Успешное завершение, путь к файлу. |
| `error` | строка | Ошибка (последние строки stderr). |

## Технические детали

- **Прогресс.** Используется `--progress-template` с префиксом `__PROGRESS__` и `--newline`;
  сервер построчно парсит stdout `yt-dlp` и пересылает события клиенту. В веб-режиме
  загрузчик `ffmpeg` не задаётся (в отличие от CLI), чтобы получать корректные проценты от
  нативного загрузчика yt-dlp; склейка дорожек всё равно делается через FFmpeg.
- **Имя файла.** Передаётся флагом `--print "after_move:__FILE__%(filepath)s"` — итоговый
  путь приходит после перемещения/склейки и попадает в событие `done`.
- **Отмена.** Команды запускаются через `exec.CommandContext(r.Context(), …)` — закрытие
  вкладки/соединения прерывает запущенный `yt-dlp`.
- **Cookies.** Общий хелпер `cookieArgs()` строит флаги (`--cookies` / `--cookies-from-browser`)
  и используется как веб-режимом, так и `downloadVideo()` в CLI.
