# Бриф 01 — go_yt_dwn: нативные оболочки, редизайн, транскрибация

**Дата:** 2026-07-31. Владелец: Ali (Go-бэкендер, учится). Проект — Go-обёртка над
yt-dlp/FFmpeg с веб-оболочкой (`ui.go` — весь UI одной HTML-строкой, `web.go` — сервер
и обработчики, `deps.go` — автоустановка зависимостей, `main.go` — консольный режим).

Цель: превратить утилиту в полноценную программу — своё окно вместо вкладки браузера,
современный интерфейс, плюс локальная транскрибация видео (whisper).

## Разделение работ (две зоны, работают параллельно)

- **Зона A (дизайн и оболочки):** `ui.go`, новые `app/` (macOS) и `app-windows/`,
  `build.sh`/Makefile, README. Реализует UI транскрибации по контракту ниже — против
  ещё не существующего бэкенда (заглушка допустима, но вёрстка и состояния — рабочие).
- **Зона B (whisper-бэкенд):** новый `whisper.go`, правки `web.go` и `deps.go`,
  `docs/whisper.md`. UI НЕ трогает (`ui.go` — чужая зона).

Общий контракт API (зона B реализует, зона A использует):

```
POST /api/transcribe   {"path":"...","lang":"ru|auto","model":"base|small|medium|large-v3","format":"txt|srt|vtt"}
                       → {"jobId":"..."}   400 — файла нет / формат не поддержан
GET  /api/transcribe/progress?id=  → {"state":"queued|extracting|transcribing|done|error",
                                      "percent":0..100,"eta":сек,"error":"","outPath":"...","preview":"первые строки"}
POST /api/transcribe/cancel {"id":"..."}
GET  /api/whisper/status → {"installed":bool,"models":[{"name":"...","size":байт,"downloaded":bool}],"busy":bool}
POST /api/whisper/install {"model":"..."}  → скачивание модели, прогресс тем же /progress (id="model:<name>")
```

## Зона A — задачи

1. **Редизайн интерфейса.** У проекта своей дизайн-системы нет → база `ui-ux-pro-max`
   ведущая: выбрать стиль, палитру и шрифтовую пару ИЗ БАЗЫ (обосновать выбор в отчёте),
   не выдумывать. Ориентир: утилита для медиа, тёмная тема уместна, но обязательны обе
   (light/dark по `prefers-color-scheme` + ручной переключатель). Сохранить
   самодостаточность: всё инлайном в `ui.go`, никаких CDN, шрифты — системные
   (веб-шрифты нельзя: программа работает без интернета).
2. **Экраны:** (а) вставка ссылки + выбор качества/формата + куки-источник (всё это уже
   есть в логике — переработать подачу); (б) **очередь загрузок** с прогрессом,
   отменой, повтором; (в) история с открытием папки; (г) панель транскрибации
   (по контракту выше): выбор файла (скачанного или с диска через drag-n-drop),
   язык, модель, формат вывода, прогресс, превью текста, кнопка «открыть в Finder».
3. **Состояния обязательны:** пусто, загрузка, ошибка (нет сети / битая ссылка /
   yt-dlp не смог), отсутствие зависимостей с кнопкой «установить».
4. **Нативные оболочки** — тем же способом, что в `~/Desktop/myProjects/dupe-hunter`
   (изучи `app/DupeHunterApp.swift` и `app-windows/`, это рабочие образцы):
   - macOS: Swift + WKWebView, .app-бандл, иконка, ad-hoc подпись, Cmd+Q гасит сервер,
     single instance, Edit-меню (копипаста), меню «Вид» с масштабом.
   - Windows: go-webview2 + user32, exe без консоли (`-H windowsgui`), Job Object
     против сирот, single instance, иконка .ico.
   - Цели сборки: `make app` / `make windows-app` (или расширить `build.sh` — как
     удобнее проекту; консольный и веб-режимы должны остаться рабочими).
   - ВАЖНО: не копировать код dupe-hunter вслепую — переносить осмысленно, имена/бандл
     свои (`dev.rocket.go-yt-dwn`, «Video Downloader»).

## Зона B — задачи

1. **whisper.cpp**: собрать/поставить бинарь и модели тем же принципом, что уже принят
   в проекте для yt-dlp/FFmpeg (`deps.go`): искать в системе → иначе скачать в `tools/`.
   На macOS arm64 — сборка с Metal (быстро на M-чипах), на Windows — готовый релизный
   бинарь. Модели качать по требованию (`base` ~150 МБ … `large-v3` ~3 ГБ), хранить
   рядом с tools, докачку не терять (resume/докачка или атомарная замена).
2. **Пайплайн:** видео → FFmpeg вытаскивает дорожку (16 кГц моно wav) → whisper →
   вывод в txt/srt/vtt рядом с исходником. Прогресс парсить из вывода whisper
   (проценты/таймкоды), отдавать по контракту. Отмена = убить процесс и подчистить temp.
3. **Edge cases:** видео без звуковой дорожки (понятная ошибка); очень длинные файлы
   (несколько часов — не держать в памяти, temp в системной temp-папке с очисткой);
   параллельные запросы (очередь на один процесс whisper, `busy` в статусе); пути с
   пробелами и кириллицей; отсутствие модели (предложить установку); нехватка места
   на диске под модель — проверить заранее; отмена во время скачивания модели.
4. **Русский язык:** по умолчанию `lang=ru`, модель по умолчанию — та, что даёт
   вменяемое качество на русском при разумном весе (проверь на практике `small` vs
   `medium`; рекомендацию зафиксируй в `docs/whisper.md` с замерами времени на M5).
5. **Честно задокументировать:** whisper НЕ разделяет говорящих (диаризации нет),
   написать это в доке и показать в UI подсказкой (текст подсказки — зоне A).
6. Тесты: юнит-тесты парсинга прогресса и построения аргументов; интеграционный —
   на коротком сгенерированном FFmpeg аудио (синус/тишина) прогнать реальный whisper
   с моделью `base`, проверить, что процесс отрабатывает и файл создаётся.

## Общие требования

- Русские тексты интерфейса и документации; код идиоматичный Go, читаемый (владелец учится).
- Не ломать: консольный режим, автоустановку зависимостей, кросс-сборку релизов.
- `go vet ./...`, `go build ./...` зелёные; сборки под macOS и Windows проверить.
- Коммиты осмысленные, по пунктам. Работать только в своей зоне; при конфликте
  `git index.lock` — подождать и повторить.

## Критерии готовности

- Приложение запускается двойным кликом на маке (окно, иконка, не браузер), exe
  собирается под винду; веб- и консольный режимы живы.
- Скачивание работает как раньше; интерфейс переработан, обе темы, все состояния.
- Транскрибация: реальный файл → текст с таймкодами; прогресс идёт; отмена работает.
- Скриншоты новых экранов (light+dark) в `docs/screenshots/`.
