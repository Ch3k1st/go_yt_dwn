# Бриф 02 — go_yt_dwn: расширение браузера («глаза» внутри страницы)

**Дата:** 2026-07-31. Решение владельца: делаем расширение + установку через кнопку
в программе с наглядной инструкцией. **В магазин Chrome НЕ публикуем** — установка
распакованной папкой через режим разработчика, это осознанный выбор.

## Зачем

yt-dlp работает снаружи и разбирает сайт по заранее написанным правилам: ломается на
неизвестных сайтах, коротких подписанных ссылках и там, где нужен вход. Расширение
живёт внутри сессии браузера и видит реальные запросы плеера — адреса приходят уже
с куками, заголовками и подписями. Программа остаётся «компаньоном», который качает
и склеивает (ровно как у VideoDownloadHelper).

**Граница, не обсуждается:** контент с DRM (Widevine/FairPlay — Netflix, Кинопоиск
и подобные) не поддерживаем. Никаких попыток снять защиту, расшифровать ключи или
обойти EME. Ловим только незащищённые потоки. Если в перехвате виден DRM-манифест —
показываем «защищено DRM, скачивание не поддерживается» и не предлагаем действий.

## Архитектура

```
браузер ──(webRequest, наблюдение)── расширение ──HTTP POST──> localhost:8080 программы
                                          │                          │
                                    popup со списком           очередь загрузок
                                    найденного медиа           (yt-dlp + ffmpeg)
```

### Расширение (`extension/`, Manifest V3)

- **Наблюдение за трафиком:** `chrome.webRequest.onBeforeRequest`/`onSendHeaders`
  (в MV3 наблюдательный webRequest доступен — блокирующий не нужен и не используется).
  Ловим: `.m3u8`, `.mpd`, `.mp4`, `.webm`, `.m4s`, `.ts`, а также ответы с
  `Content-Type: video/*`, `application/vnd.apple.mpegurl`, `application/dash+xml`.
- **Группировка по вкладке:** для каждой вкладки — свой список находок; сегменты
  потока (`.ts`/`.m4s`) НЕ показывать по одному: если есть манифест — показываем его,
  сегменты сворачиваем. Дедупликация по URL без query-подписи.
- **Заголовки — ключевая часть.** Многие ссылки отдаются только со своим `Referer`,
  `User-Agent`, `Origin`, `Cookie`. Их надо запомнить из `onSendHeaders` и передать
  программе: yt-dlp умеет `--referer` и `--add-header`. Без этого половина ссылок
  вернёт 403 — это главная причина, по которой «ссылка есть, а не качается».
- **Popup:** список найденного по текущей вкладке — тип (HLS/DASH/файл), качество
  (если видно из манифеста), размер (если известен), длительность; кнопка «Скачать»
  на каждой строке и «Скачать всё». Состояние: программа доступна / не запущена
  (с подсказкой «запустите Video Downloader»).
- **Значок на иконке:** количество найденного на вкладке.
- **Никакой аналитики, никаких внешних запросов** — расширение общается только
  с `127.0.0.1`. Разрешения в манифесте — минимально необходимые, каждое прокомментировать
  в `extension/README.md` (пользователь увидит их при установке и должен понимать зачем).

### Связь с программой

- `POST http://127.0.0.1:8080/api/capture` (порт по умолчанию из `main.go`; если занят,
  сервер берёт свободный — расширение пробует диапазон 8080–8090 и запоминает рабочий).
- Тело: `{token, url, pageUrl, title, kind:"hls|dash|file", headers:{referer,userAgent,cookie,origin}, size?, quality?}`
- Ответ: `{ok:true, queued:true, id}` либо ошибка.
- **Токен обязателен.** Иначе любой сайт в браузере сможет слать команды программе.
  Программа генерирует токен при первом запуске (`tools/extension-token` или конфиг),
  и **впечатывает его в файл `extension/config.js` при распаковке расширения** —
  пользователю ничего копировать не надо. Запросы без верного токена — 403.
  CORS: разрешаем только `chrome-extension://*` источники и только для `/api/capture`.
- Проверка живости: `GET /api/ping` → `{app:"go_yt_dwn", version}` (без токена, чтобы
  popup мог показать «программа не запущена»).

### Кнопка «Расширение» в программе

1. **Определение браузеров.** macOS: искать в `/Applications` и `~/Applications`
   (Chrome, Яндекс.Браузер, Edge, Brave, Opera, Vivaldi, Arc, Chromium, Firefox).
   Windows: реестр `HKLM\SOFTWARE\Clients\StartMenuInternet` + типовые пути
   в `Program Files`/`LocalAppData`. Возвращать имя, путь, движок (chromium|firefox).
2. **Подготовка:** распаковать расширение в стабильную папку рядом с зависимостями
   (`tools/extension/`), вписать токен в `config.js`, обновлять папку при новой версии
   программы (расширение подхватит после «Обновить» в браузере).
3. **Помощь в установке:** открыть страницу расширений выбранного браузера
   (`chrome://extensions` для chromium — ПРОВЕРИТЬ, открывается ли это через `open -a`;
   если браузер игнорирует такой аргумент, честно показать путь и попросить вставить
   вручную) и одновременно открыть папку в Finder/Проводнике. Показать инструкцию:
   включить «Режим разработчика» → «Загрузить распакованное расширение» → выбрать папку.
4. **Проверка успеха:** программа ждёт первый `/api/ping` от расширения и показывает
   «расширение подключено ✓». Для Firefox (если найден) — отдельная короткая инструкция
   через `about:debugging` с честной пометкой, что до перезапуска браузера оно временное.

## Edge cases

1. Программа не запущена, а пользователь жмёт «Скачать» в popup → понятная подсказка,
   а не молчаливая ошибка; попытка на всех портах диапазона.
2. Сайт с DRM → метка «защищено DRM», кнопки скачивания нет.
3. Прямые ссылки на огромные файлы (торрент-подобные mp4 на несколько ГБ) — не тянуть
   в память ничего, просто передать URL программе.
4. Много вкладок с видео → списки не смешивать; при закрытии вкладки — чистить её записи
   (иначе память расширения растёт бесконечно).
5. Один и тот же поток в нескольких качествах (мастер-манифест) → показывать один
   мастер, качество выбирается уже в программе.
6. Приватные вкладки: расширение по умолчанию в них не работает — так и оставить,
   отдельно не включать.
7. Токен утёк/сменился (переустановка программы) → 403 с понятным текстом
   «переустановите расширение из программы» в popup.
8. Расширение обновилось, а программа старая (или наоборот) → в `/api/ping` отдавать
   версию протокола, расхождение — предупреждение в popup.
9. Не запускать программу автоматически из расширения (браузер этого и не может) —
   только подсказка.

## Что НЕ делаем

Публикацию в Chrome Web Store и любые магазины; подпись Firefox через AMO; блокирующий
webRequest и модификацию трафика; сбор какой-либо статистики; обход DRM.

## Критерии готовности

- Расширение ловит видео на обычном сайте (проверить на реальном: например, любой сайт
  с HLS-плеером — YouTube тоже подойдёт как smoke-тест, хотя его yt-dlp берёт и так).
- Нажатие «Скачать» в popup ставит задачу в очередь программы, файл скачивается.
- Заголовки передаются: проверить на ссылке, которая без `Referer` отдаёт 403.
- Кнопка в программе находит установленные браузеры (проверить на реальной машине),
  распаковывает расширение с токеном, открывает нужные окна.
- Запрос без токена → 403; запрос с токеном из расширения → 200.
- `go vet`, `go build`, `go test` зелёные; кросс-сборка под Windows не сломана.
- `docs/extension.md`: как устроено, как установить, что не поддерживается (DRM),
  какие разрешения и зачем.
